# Changes to the vendored pret/pokefirered tree

> This log comes from the development repository this one was extracted from. The `docs/`, `tests/`, `tools/` (other than `tools/mirror`) and `others/` paths it cites (verification reports, differential tests against mGBA, fuzzing and coverage tools) are not included here; the changes listed are exactly the ones this repository builds. Here the changes to pret's files ship as `native/pokefirered.patch`, which `tools/fetch_game.sh` applies to pret's files at the upstream commit.

Upstream: see UPSTREAM.txt (pret/pokefirered @ 037335f4c). Every change to an
upstream file is guarded by `PORTABLE` (the GBA build is unchanged). Owner:
native-build agent (M1); mirror memory layout changes by the m1b agent (M1b).
Verify with `diff -ru others/pokefirered/<file> game/<file>` (`include/gba/io_reg.h`
is identical to upstream again since M1b).

New files (not upstream): `Makefile.native` (native build), `native/` (build
tools: `as_x86.py` ARM-GAS data -> i386 GAS, `mirror_sections.py` (per-object
section renames for the mirror layout, libc redirects), `compare_data_objs.py`),
`include/gba/portable_abi.h` (force-included under PORTABLE: ARM struct rule,
Port_* declarations), this file. The mirror memory layout (M1b,
docs/MIRROR_LAYOUT.md) is generated by `../tools/mirror/gen_ld.py` and checked
by `../tools/mirror/check_addresses.py` (see "Mirror memory layout" below). Generated by the normal pret asset pipeline
during the native build (not edited): `include/constants/{layouts,map_groups,
map_event_ids,heal_locations,region_map_sections}.h`, `src/data/*.h` from JSON,
`data/maps/**/*.inc`, `data/layouts/*.inc`, graphics/sound binaries, tool
binaries in `tools/`.

"Behavior change" is about game-visible state at frame boundaries compared with
the retail ROM (FireRed USA v1.0). "None" means the native code computes the
same values the ROM computes.

## Retail hardware faults and terminal statuses (platform, robustness agent)

No game source change; documented here because it defines what game code does where the
native CPU would fault (docs/ROBUSTNESS.md). platform/memfault.c handles SIGSEGV/SIGBUS/
SIGFPE/SIGILL raised by game code: a memory operand in the GBA BIOS region is redirected to a
shadow filled with the BIOS open-bus word (`gPortBiosPrefetch`), writes to the BIOS region,
unmapped memory or the ROM are discarded, mirrors of EWRAM/IWRAM/palette/VRAM/OAM/flash are
mirrored, `x / 0`, `x % 0` and `INT_MIN / -1` get agbcc's results; the instruction is
re-executed unchanged otherwise. Everything that cannot be reproduced (CPU open bus without a
ROM-opcode patch, a call through such a pointer, an illegal instruction, a stack overflow, the
hang watchdog) ends the environment with a terminal status (`PORT_FRAME_TERMINAL`,
`Port_GetTerminal`) instead of the process; so do `Port_Fatal` (INTERNAL), `Port_Unsupported`
(UNSUPPORTED) and the new `Port_Hang`/`Port_Crash`/`Port_Inexact` declared in
`include/gba/portable_abi.h` (with `Port_SpinPoll` and `Port_LoadWithOpenBus`). platform/bios.c:
`Div(x, 0)` with |x| > 1 -> `Port_Hang` (the real BIOS loops; mGBA's HLE returns ±1);
`Port_BiosOpenBus*` above 0x3FFF -> `Port_Inexact`.
A terminal status (or soft reset) leaves the game stack through `Port_LeaveGameStack` (platform/frame.c: Port_CallOnGameStack's epilogue on the host stack) instead of returning through the body's own frame: a game-code stack smash can overwrite every frame up to the top of the game stack, and the return through `FrameBody`'s smashed return address used to jump to 0 outside game code and abort the process (fix agent). Not modelled: such a smash also overwrites the native-only `.pnstate` variables above the stack (`gPortBiosPrefetch`, `sDma`, flash and timer-1 state, `sTerminal`); the environment has ended at that point.
`src/m4a.c` `MPlayStart`, `CgbSound`, `ply_memacc` (PORTABLE): `MPlayStart` calls `Port_SoundSongCheck(songHeader, mplayInfo->trackCount)` first; `CgbSound` calls `Port_SoundReadCheck(wavePointer, 16)` before copying a CGB wave to the wave RAM and `ply_memacc` `Port_SoundReadCheck(memAccArea, 256)` before its operands (Codex probes CX-017). With the default logic-only sound mixer (platform/sound.c) the PCM buffer is not computed, so sound data read from `gSoundInfo.pcmBuffer` would differ from the hardware; the check (with the platform's checks of command fetches, voice and tone entries, wave headers/data at note start and the mixer's sample spans) ends the environment as INEXACT in that case and does nothing otherwise (no read, same instructions in both mixer modes). Retail sound data is in the ROM (the memacc area at 0x030073C0 and the cry songs at 0x03006F00 lie outside the buffer), so only a stray sound pointer gets there; IWRAM mirrors are mapped to the buffer's offsets (CX-018) (Codex review CX-010; `ctest -R sound_mix_pcm_alias`, 10 cases). No behavior change.

## Narrow return values through wider function types (fix agent; Codex's ABI scan, CL-004)

agbcc's callee extends a `u8`/`s8`/`u16`/`s16` (`bool8`, `bool16`) return value to all of r0
(`lsls/lsrs` or `lsls/asrs` before the return, e.g. `IsActiveOverworldLinkBusy` and
`FldEff_PopOutOfAsh` in the ROM); GCC/i386 defines only AL/AX and leaves the extension to the
caller. A caller that calls such a function through a wider type therefore reads garbage in the
upper bits natively. GCC has no option to make the callee extend (i386's
`TARGET_PROMOTE_FUNCTION_MODE` promotes pointers only), so every caller that can observe the
upper bits calls through the function's real type. Inventory: a libclang scan of all 283
translation units (22 cross-TU declaration/definition differences, 92 typed function
conversions, 17 casts from integers, specials and field-effect script natives), plus the 28
`loadfadedpal_callnative` field-effect natives the scan did not list.

## Mirror memory layout (M1b, docs/MIRROR_LAYOUT.md)

The native executable maps the GBA's memory at the GBA's addresses: EWRAM
0x02000000 (256 KiB), IWRAM 0x03000000 (32 KiB), I/O 0x04000000, palette
0x05000000, VRAM 0x06000000, OAM 0x07000000, flash 0x0E000000 (128 KiB, both
banks), all NOLOAD sections of `<build dir>/game-native/mirror.ld` (`build/native/mirror.ld` for a manual make), generated by
`../tools/mirror/gen_ld.py` from `../reference/rom_symbols_detailed.tsv` and the
objects' section tables. Every one of the ROM's 907 EWRAM/IWRAM symbols is
either at its ROM address with its ROM size (886) or a documented gap (21);
`../tools/mirror/check_addresses.py` verifies that after every link. The
executable's code and read-only data are linked at 0x08000000
(`-Ttext-segment`), inside the GBA's ROM window.

Documented gaps (ROM RAM symbols without a native counterpart; their bytes stay
reserved and zero natively): the agbcc newlib data `impure_data`, `_impure_ptr`,
`__mb_cur_max`, `lc_ctype.3`, `last_lc_ctype.4`, `__malloc_av_`,
`__malloc_trim_threshold`, `__malloc_top_pad`, `__malloc_sbrk_base`,
`__malloc_max_sbrked_mem`, `__malloc_max_total_mem`, `__malloc_current_mallinfo`
(EWRAM 0x0203F468..0x0203FBB0), `heap_end.63`, `monitor_stdin/stdout/stderr`,
`openfiles`, `errno`, libgcc's two `thenan.3` (IWRAM), and the linker symbol
`end`. The game never calls newlib's malloc/stdio. Aliases: the linker-script
symbol `gHeap` is `platform/hw.c` `gHeap`; `m4a_1.s`'s `sDecodingBuffer` is
`platform/sound.c` `sDecodingBuffer` (both `EWRAM_DATA`/`IWRAM_DATA`).

Native-only state (`.pnstate`, 0x10000000, part of every snapshot; no game
object has any): `gPortGameStack` (32 KiB, the stack game code runs on; at the
bottom of .pnstate so that an overflow faults), `gPortBiosPrefetch` (BIOS open
bus value), `sDma`/`sDmaTransferRegister` (DMA latches), `gPortFlashBank`/
`sFlashCmdState` (flash chip model), `sTimer1Values/Count/Next` (timer 1 value
sequence), `SoundMainRAM` (the 2 KiB zero source of m4aSoundInit's machine-code
copy), `sTerminal` (frame.c: the environment's terminal status, docs/ROBUSTNESS.md).

Differences from the ROM's RAM that the mirror layout cannot remove (masked or
classified by `../tools/mirror/compare_ram.py`, each explained in
docs/DEVLOG.md, m1b agent): `IntrMain_Buffer` and `SoundMainRAM_Buffer` (copies
of ARM machine code on the GBA, of zero arrays natively), `sRfuAPIBuffer`'s
fastCopy buffer/pointer and STWI block1 (machine-code copies), `PollFlashStatus`
(points to a machine-code copy on the GBA stack), the GBA stack area
0x03007480..0x03007FEF (native game code runs on the .pnstate stack), the
debug variables `sVcountBeforeSound`/`sVcountAfterSound`/`sVcountAtIntr`, RAM
words that store a pointer to the stack (e.g. `gSprites[i].template` of a
sprite created from a stack-local template), and struct padding copied from
uninitialised stack locals. Behaviour-level residuals that are not caused by a
source change are listed with their root causes in docs/DEVLOG.md (m1b agent):
lag VBlanks replayed at another point of the frame body (F2), the VCOUNT policy
(`sGpuRegWaitingList`, DISPSTAT status bits in `sGpuRegBuffer`, F3),
`gRfuSIO32Id` (F4, src/librfu_sio32id.c row), and checksums over structs that
hold ROM pointers (F6: `enigmaBerry.checksum`; native code/rodata addresses are
not the ROM's).
